
# עץ קטגוריות מקצועי + מבנה 3 רמות + Grid כרטיסים

## 1. עקרונות מנחים
- מבנה קבוע: **סוג פרויקט → תחום ראשי → שירות → ספקים**.
- בכל רמה מוצגים **רק פריטים של אותה רמה**, ללא ערבוב.
- כל תחום/שירות מוצג ככרטיס מרובע ב-Grid של **3 בשורה** במובייל, בדיוק כמו 3 כרטיסי סוגי הפרויקט.
- כניסה ישירה לכל תחום מותרת — אין חובת מעבר לפי סדר.
- שפה עיצובית קיימת: אותם צבעים (`#0E6B5A` וכו'), רדיוסים (`rounded-[20px]`), הצללות, מצב selected. **לא Timeline, לא Accordion, לא רשימות ארוכות.**

## 3. שינויים בקוד (טכני)

1. **`src/lib/stageCatalog.ts`**
   - להרחיב `STAGE_LABELS` עם כל השלבים לעיל (מפתחות חדשים: `pre-plan`, `turnkey` בבנייה חדשה; שלבי שיפוץ מלאים; שלבי בניין מלאים).
   - שדה `order` מגדיר את הסדר לפי מסע המשתמש.

2. **`src/pages/resident/CategoriesList.tsx`**
   - להסיר `StageCard` השורתי.
   - להציג את השלבים כ־**Grid `grid-cols-3` של כרטיסים מרובעים** (אותו סגנון כמו `ProjectTypeCard`): אייקון/אמוג'י אחיד, שם השלב, chevron קטן בפינה, shadow עדין, פינות מעוגלות, מצב פעיל בצבע ה־accent של הפרויקט.
   - להוסיף שלבים חסרים גם אם אין להם עדיין קטגוריות ב־DB (מוצגים עם `serviceCount=0`).

3. **`src/pages/resident/CategoryStages.tsx`** (שלב 3 — שירותים)
   - להחליף את רשימת השירותים השורתית ב־**Grid `grid-cols-3` של כרטיסים** באותו סגנון בדיוק (אייקון + שם שירות + chevron קטן + shadow עדין).
   - כרטיס עם 0 ספקים יראה תגית "בקרוב" בפינה במקום מספר ספקים.
   - שמירת ה־hero העליון ו־breadcrumb (עוזרים לניווט).

4. **מיגרציית DB (`category_project_stages`)** — לא חובה בשלב זה. העיצוב יעבוד עם הנתונים הקיימים; שלבים ריקים יוצגו עם "בקרוב". אחרי אישור העיצוב אפשר להוסיף עוד מיפויים בפועל.

## 4. מה לא משתנה
- זרימת הספקים (`CategorySuppliers.tsx`) נשארת כמו שהיא — היא כבר טובה.
- צבעי המותג, פונטים, כפתורים, הצללות, `BottomNav` — הכול נשאר.
- מסך `CreateDemand` (ה־wizard) — לא נוגעים.
